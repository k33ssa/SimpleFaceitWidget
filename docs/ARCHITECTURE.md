# Архитектура

```
          ┌──────────── App (macOS / iOS, SwiftUI) ────────────┐      ┌──── Widget extension ────┐
          │ Обзор · Матчи · Графики · Настройки · Диагностика  │      │ Provider (AppIntent)     │
          │ Онбординг (ключ → поиск ника) · импорт ELO WebKit  │      │ StyleIntent · Refresh    │
          └───────────────┬────────────────────────────────────┘      └──────────┬───────────────┘
                          │            FaceitUI (раскладки, компоненты)          │
                          └──────────────┬───────────────────────────────────────┘
                                         ▼
                         StatsRepository.refresh(force:)  ← единственная точка обновления
                         │  1. кэш свежий? → вернуть без сети
                         │  2. FileLock (flock) — один процесс за раз; после захвата снова проверить кэш
                         │  3. /players/{id} ∥ /games/cs2/stats?limit=100 ∥ /stats/cs2
                         │  4. снимок ELO; /matches/{id} только для новых матчей окна (кэш навсегда)
                         │  5. арт карт, аватар (один раз) → Dashboard → dashboard.json
                         ▼
        App Group container:  FaceitData/faceit.sqlite (снимки ELO, матчи, журнал)
                              FaceitData/dashboard.json, avatar.img, maps/*.img, .apikey (fallback)
```

## Обновление и честность времени

* WidgetKit не обновляет в реальном времени. Провайдер просит перезагрузку на `fetchedAt + интервал` (минимум +5
  минут); система может сделать это позже. Интервал — 15/30/60/120/240 мин, по умолчанию 30.
* Приложение, пока открыто, обновляет по тому же интервалу. На iOS в фоне работает `BGAppRefreshTask`: держит кэш и
  снимки ELO свежими. После получения новых данных приложение вызывает `WidgetCenter.reloadAllTimelines()`.
* В виджете и приложении показывается время последнего **успешного** получения данных (`fetchedAt`). Если
  обновление не удалось или данным больше двух интервалов, рядом стоит ⚠︎.

## Без дублирующих запросов

* Кэш младше 90 % интервала → запросов нет вообще. Так N виджетов, перезагрузившихся одновременно, дают один набор
  запросов.
* Межпроцессная блокировка `flock` на `refresh.lock`. Второй процесс ждёт, затем видит свежий кэш и выходит.
* Принудительное обновление (кнопка) раньше чем через 20 с после прошлого — тоже из кэша.
* `/matches/{id}` закончившегося матча не меняется → кэшируется навсегда. В обычном обновлении это 0–2 запроса.
* Итого одно обновление — 3 запроса плюс новые матчи. Первое обновление — 3 + 21.

## Ограничения API и ошибки

* Лимит шлюза 20 запросов/с (заголовок `ratelimit-limit: 20, 20;w=1`, замерено 14.11.2026). Матчи запрашиваются
  пачками по 4.
* Повторы: сеть, 5xx, 429 — до 3 попыток с экспоненциальной паузой (0.8 / 1.6 / 3.2 с + случайный разброс).
  При 429 пауза берётся из `Retry-After` / `ratelimit-reset`. Ошибки 400 `invalid_token`, 401, 403, 404 не
  повторяются.
* Все ответы и ошибки пишутся в общий журнал SQLite с меткой процесса (app / widget). Его видно на экране
  «Диагностика», там же кнопка «Проверить связь».

## API-ключ

* Data API требует ключ. Нативное приложение — клиентский код, и вшитый ключ из него можно извлечь. Поэтому:
  * пользователь вводит свой ключ в онбординге; перед сохранением он проверяется одним запросом;
  * ключ хранится в Data Protection Keychain с access group = App Group. Если подписи без профиля Keychain
    недоступен (macOS, `errSecMissingEntitlement`), ключ лежит в файле 0600 внутри App Group-контейнера: на macOS
    его защищает песочница, открыть могут только приложения той же команды и группы;
  * в журнал и UserDefaults ключ не попадает;
  * для личных сборок можно положить `FACEIT_API_KEY` в `Config/Secrets.xcconfig` (в .gitignore). Ключ попадёт в
    Info.plist и при первом запуске перенесётся в защищённое хранилище. **Публичные релизы собирать без него.**
* Свой прокси-сервер полностью спрятал бы ключ. Но тогда нужен сервер, а это другой масштаб проекта (`TODO.md`).

## Модули и зависимости

Внешних зависимостей нет: Foundation, SwiftUI, WidgetKit, AppIntents, Charts, WebKit, SQLite3 (системная).
`FaceitKit` — без UI, тестируется `swift test`. `FaceitUI` зависит от `FaceitKit` и используется приложением,
виджетом и `SnapshotTool`.
