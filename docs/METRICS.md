# Метрики: источник, формула, период, пропуски

Все числа приходят из официального FACEIT Data API v4 (`https://open.faceit.com/data/v4`) или считаются из его
ответов. Единственное исключение — точная история ELO с faceit.com (раздел «ELO», пункт 3), она помечена как неофициальная.
Демо-чисел в приложении нет. Код расчётов: `Packages/FaceitKit/Sources/FaceitKit/Stats/`.

**Окно «последние 20»** — 20 последних записей `GET /players/{id}/games/cs2/stats` (одна запись = одна карта; в BO1
матчмейкинге карта = матч). Порядок в ответе: от новых к старым. На экране лента идёт **слева старые, справа новые**.
За одно обновление берётся 100 записей (`limit=100`, один запрос): 20 для окна, остальные для графиков истории.

| Метрика | Источник | Формула | Период | Если данных нет |
|---|---|---|---|---|
| Current ELO | `GET /players/{id}` → `games.cs2.faceit_elo` | как есть | на момент обновления | «—»; без `games.cs2` → ошибка «нет профиля CS2» |
| Уровень | `games.cs2.skill_level` | как есть | сейчас | «—» |
| До следующего уровня | ELO + границы уровней CS2 (статья поддержки FACEIT «CS2 Elo and skill levels») | нижняя граница уровня+1 − ELO | сейчас | для 10 уровня — «max level» |
| Победы / поражения | `stats["Result"]` (`"1"` победа) | счёт | 20 игр | запись без `Result` пропускается целиком |
| Win Rate | то же | победы / игры × 100 | 20 игр | «—» при 0 игр |
| K/D | `Kills`, `Deaths` | Σ убийств / Σ смертей (отношение сумм, не среднее отношений) | 20 игр | Σ смертей = 0 → Σ убийств; нет игр → «—» |
| HS % | `Headshots`, `Kills`; запасной `Headshots %` | Σ хедшотов / Σ убийств × 100; если нет `Headshots` — среднее `Headshots %` | 20 игр | «—» |
| Avg Kills / Deaths / Assists | `Kills`, `Deaths`, `Assists` | Σ / число игр | 20 игр | «—» |
| ADR | `Damage`, `Rounds`; запасной `ADR` | Σ урона / Σ раундов по играм, где есть оба; иначе среднее `ADR` | 20 игр | у игр до ~июня 2024 ADR нет — они не считаются нулём, показывается число игр с ADR |
| Rating 1.0 | `Kills`, `Deaths`, `Rounds`, `Double/Triple/Quadro/Penta Kills` | HLTV Rating 1.0: (KPR/0.679 + 0.7·SPR/0.317 + RMK/1.277)/2.7, где 1K = K − 2·2K − 3·3K − 4·4K − 5·5K; считается по суммам окна | 20 игр | игры без мультикиллов исключаются; если таких нет — «—» |
| Rating 2.0/3.0, KAST | — | **не считаются**: FACEIT не отдаёт KAST, трейды, данные по раундам | — | не показываются |
| История WR, K/D, HS%, ADR | те же поля | скользящее окно 20 игр по последним 100 | до 81 точки | точки с неполным окном не строятся |

## ELO за 20 игр (главная тонкость)

Официальный Data API **не отдаёт ELO по матчам** (проверено по swagger и живым ответам, `docs/API_RESEARCH.md` §7).
Поэтому изменение считается из трёх источников, по убыванию точности:

1. **Свои снимки** (`exact`). При каждом обновлении сохраняется пара «ELO сейчас + самая новая игра». Такой снимок —
   точное «ELO после этой игры». Если между двумя снимками ровно одна игра, её дельта точная. Если несколько —
   точна их сумма, а по играм она делится по оценке (`constrained`). Для одной игры берётся самый поздний снимок:
   ранний мог быть сделан до того, как FACEIT пересчитал ELO.
2. **Оценка** (`estimated`) для игр, которые не покрыты снимками: Δ = 50 · (результат − p), где p —
   `teams.<фракция игрока>.stats.winProbability` из `GET /matches/{id}`. K = 50 — эмпирика сообщества, не
   официальная константа. С 2025 года FACEIT для уровней 1–9 добавляет небольшую поправку за личную игру, поэтому
   оценка помечается «≈». Матчи с `calculate_elo = false` дают 0 (`unrated`).
3. **Точная история с faceit.com** (неофициально). Эндпоинт сайта
   `www.faceit.com/api/stats/v1/stats/time/users/{id}/games/cs2` отдаёт `elo` после каждого матча. Он закрыт
   Cloudflare для запросов не из браузера (403, проверено 14.11.2026). Поэтому приложение запрашивает его только
   изнутри WebKit-страницы faceit.com, в обычной сессии пользователя: так же, как это делает сам сайт. Защиту оно
   не обходит. Полученные значения сохраняются как снимки из п. 1, после чего дельты становятся точными.

**Изменение за 20** = ELO сейчас − ELO после 21-й с конца игры (то есть до самой старой игры окна). Оно точное, если
ELO после 21-й игры известно из снимка. Иначе показывается со знаком «≈», а на экране подробностей написано, сколько
игр покрыто точными данными.

## Время обновления

Показывается момент последнего **успешного** получения данных (`Dashboard.fetchedAt`), а не момент перерисовки виджета.
Если последняя попытка обновления не удалась, данные старше двух интервалов обновления, а в виджете рядом со
временем стоит значок ⚠︎. Текст ошибки виден в приложении на экране «Диагностика».
